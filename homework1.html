Toy Elliptic Curve

A private key is just a number k. Multiplying a base point G on an elliptic curve by k gives the public key Q = kG: easy to compute, but hard to reverse. Here the idea is shown on a toy curve small enough to follow by hand.

Summary

The curve is y² = x³ + 7 (mod 17) with base point G = (1, 5) and private key k = 6. Computing 1G, 2G, …, 6G gives the toy public key Q = 6G = (5, 8). The same result comes out of the faster double-and-add method.

The curve has 17 points plus the point at infinity, so 18 elements in total. The point G = (1, 5) has order 9: 9G is the point at infinity and the sequence then repeats. This example demonstrates the principle behind Ethereum's key generation, which uses the much larger secp256k1 curve for real security.

Task: Curve and Toy Public Key

Curve: y² = x³ + 7 (mod 17). The public key is Q = kG, where k is the private key and G the base point.

How it works

Point addition and doubling

To add two different points P₁ = (x₁, y₁) and P₂ = (x₂, y₂), draw the line through them. It meets the curve in a third point; reflecting that point across the x axis gives P₁ + P₂. Algebraically, the slope of the line is

λ = (y₂ − y₁) / (x₂ − x₁)

and the result is

x₃ = λ² − x₁ − x₂, y₃ = λ(x₁ − x₃) − y₁.

When P₁ = P₂ (doubling), the line is the tangent at the point and the slope is λ = (3x² + a) / (2y). For this curve a = 0, so it becomes 3x² / 2y.

All operations are done modulo 17, and "division" means multiplication by the modular inverse. For example, the inverse of 10 is 12, because 10 · 12 = 120 = 7 · 17 + 1. Negative numbers are brought back into the range 0 to 16.

Worked example, 2G = G + G with G = (1, 5):

  • λ = 3 · 1² / (2 · 5) = 3 / 10 = 3 · 12 = 36 ≡ 2 (mod 17)
  • x₃ = 2² − 1 − 1 = 2
  • y₃ = 2 · (1 − 2) − 5 = −7 ≡ 10 (mod 17)
  • so 2G = (2, 10), and 10² = 100 ≡ 15 = 2³ + 7, so it is on the curve.

Next, 3G = G + 2G: λ = (10 − 5) / (2 − 1) = 5, x₃ = 25 − 1 − 2 = 22 ≡ 5, y₃ = 5 · (1 − 5) − 5 = −25 ≡ 9, so 3G = (5, 9).

The point at infinity

The point at infinity (INF) is the neutral element of the group: P + INF = P. It appears when a point is added to its opposite −P = (x, −y), because the line through them is vertical and meets the curve nowhere else. Here G + 8G = (1, 5) + (1, 12) = INF, so 9G = INF. The order of G is therefore 9: after 9 steps the sequence goes back to G.

Double-and-add

Repeated addition needs k − 1 additions, which is hopeless for a 256-bit k. Double-and-add uses the binary expansion of k. The code keeps a running value equal to G, 2G, 4G, 8G, … (each one is a doubling of the previous), and adds it to the result whenever the corresponding bit of k is 1.

For k = 6 = 110 in binary, reading from the lowest bit: bit 0 is 0 (skip G), bit 1 is 1 (add 2G), bit 2 is 1 (add 4G). So 6G = 2G + 4G = (2, 10) + (12, 1) = (5, 8), the same as the six additions in the table. For a 256-bit k this takes at most about 256 doublings and 256 additions.

Why this is only a toy

Given Q = (5, 8), recovering k means trying k = 1, 2, 3, … until kG = Q. With 18 elements this takes six steps. On the real curve secp256k1 the group order is about 2²⁵⁶, and the best known generic attack (Pollard's rho) needs about 2¹²⁸ operations. That is the elliptic curve discrete logarithm problem (ECDLP), and the one-way behavior of Q = kG rests on it.
