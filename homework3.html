Encryption Schemes and Statistical Attacks

Comparing a toy elliptic-curve encryption scheme with the classical Caesar cipher, and exploring statistical cryptanalysis techniques to break weak cryptographic systems.

Summary

This assignment explores two encryption schemes with vastly different security properties: a toy elliptic-curve cryptosystem based on secp256k1 with restricted key space, and the classical Caesar cipher. Both schemes can be broken, but for fundamentally different reasons.

The toy ECC scheme uses proper cryptographic primitives but becomes vulnerable due to an artificially small key space (designed for educational purposes). The Caesar cipher, despite having an even smaller key space (26 keys), reveals a different weakness: its statistical patterns. This homework demonstrates how cryptanalysis adapts to exploit different vulnerabilities in cryptographic systems.

Part 1: Toy ECC Encryption/Decryption

Using the elliptic curve from Homework 1 (y² = x³ + 7 mod 17), we implement a simplified version of ElGamal encryption. The scheme maps plaintext characters to curve points, encrypts them using elliptic-curve point multiplication, and decrypts using the discrete logarithm relationship.

How it works

Key Generation

  • Choose a private key k (small range for this toy example: 1-8)
  • Base point G = (1, 5)
  • Public key Q = k·G

Encryption

For each character in the plaintext:

  1. Map character to a number (A=0, B=1, ..., Z=25, space=26)
  2. Find a point on the curve corresponding to the message value
  3. Choose a random ephemeral key r (1-8)
  4. Compute C₁ = r·G (ephemeral public key)
  5. Compute C₂ = M + r·Q (encrypted message point)
  6. Ciphertext is the pair (C₁, C₂)

Decryption

  1. Compute M = C₂ - k·C₁
  2. Map the point back to a number
  3. Convert number back to character

Note: This is a simplified toy implementation. Real ECC encryption would use proper encoding schemes and much larger curves. The restricted key space (1-8) makes this vulnerable to brute-force attacks.

Part 2: Caesar Cipher

The Caesar cipher is a simple substitution cipher where each letter is shifted by a fixed number of positions in the alphabet. With shift k=3, A becomes D, B becomes E, and so on.

How it works

Encryption

For each letter in plaintext: ciphertext[i] = (plaintext[i] + k) mod 26

Decryption

For each letter in ciphertext: plaintext[i] = (ciphertext[i] - k) mod 26

Key Space

Only 26 possible keys (0-25), where k=0 is the identity and k=26 equals k=0. This makes exhaustive search trivial.

Statistical Weakness

The cipher preserves letter frequency patterns. In English, 'E' is the most common letter (~12.7%), followed by 'T', 'A', 'O', etc. A Caesar-encrypted text will have the same frequency distribution, just shifted.

Part 3: Comparison of the Two Schemes

Property Toy ECC Caesar Cipher
Key Space 8 keys (toy), 2²⁵⁶ keys (real secp256k1) 26 keys
Encryption Method Point multiplication on elliptic curve Modular addition (shift)
Ciphertext Size Each character → 2 curve points (4 coordinates) Same size as plaintext
Statistical Properties Randomized (ephemeral key r), same plaintext produces different ciphertexts Deterministic, preserves frequency distribution
Vulnerability Small key space → brute-force attack Frequency analysis, brute-force
Security (properly configured) Strong (ECDLP hardness) None (always trivial to break)

Similarities

  • Both use a secret key for encryption and decryption
  • Both are symmetric in nature (same key encrypts and decrypts)
  • Both can be broken with exhaustive key search in their toy/weak configurations
  • Both are vulnerable when key space is small enough

Differences

  • Mathematical foundation: ECC uses elliptic curves and discrete logarithm problem; Caesar uses simple modular arithmetic
  • Randomization: ECC uses ephemeral keys (semantic security); Caesar is deterministic
  • Ciphertext expansion: ECC has significant expansion; Caesar has none
  • Statistical patterns: ECC hides patterns; Caesar preserves them
  • Modern security potential: ECC can be secure with proper parameters; Caesar cannot

Part 4: Statistical Cryptanalysis of Caesar Cipher

Given a sufficiently long ciphertext in English, we can recover the key by analyzing letter frequencies.

Attack Methods

1. Frequency Analysis

Compare the frequency distribution of letters in the ciphertext with known English letter frequencies. The shift that best aligns the distributions is likely the key.

Expected English frequencies: E (12.7%), T (9.1%), A (8.2%), O (7.5%), I (7.0%), N (6.7%), S (6.3%), H (6.1%), R (6.0%)...

2. Chi-Squared Test

For each possible shift k (0-25), decrypt the ciphertext and compute the chi-squared statistic comparing observed vs expected frequencies:

χ² = Σ (observed - expected)² / expected

The shift with the lowest χ² value is most likely correct.

3. Exhaustive Search

With only 26 keys, we can simply try all shifts and visually inspect or use dictionary matching to identify the correct plaintext.

4. N-gram Scoring (Optional)

Use bigram or trigram frequencies (e.g., "TH", "HE", "THE") to score decryption attempts. Real English text will have high n-gram scores.

Effectiveness and Limitations

  • Text length: Longer texts give more reliable frequency distributions. Short texts may have atypical frequencies.
  • Language dependency: Requires knowing the plaintext language and its frequency distribution.
  • Non-standard texts: Technical jargon, names, or special content may have unusual letter distributions.
  • Always works given enough data: Caesar cipher cannot resist statistical analysis with sufficient ciphertext.

Part 5: Breaking the Toy ECC Scheme

The toy ECC implementation restricts the private key to the range 1-8, making it vulnerable to brute-force attack despite using proper elliptic-curve cryptography.

Attack Strategy

Brute-Force Key Recovery

  1. Given: Public key Q and some ciphertext (C₁, C₂)
  2. Try all possible private keys k ∈ {1, 2, ..., 8}
  3. For each k, compute k·G and compare with Q
  4. When k·G = Q, we've found the private key
  5. Use k to decrypt the message

Comparison with Caesar Attack

Aspect Toy ECC Caesar
Attack Type Exhaustive key search Statistical + exhaustive
Complexity 8 keys to try 26 keys (or immediate with freq. analysis)
Weakness Exploited Small key space only Small key space + statistical patterns
With Proper Parameters Infeasible (~2¹²⁸ operations) Always trivial (26 keys)

Why This Doesn't Work on Real ECC

  • Key space size: secp256k1 has ~2²⁵⁶ possible keys. Trying all would take longer than the age of the universe.
  • ECDLP hardness: No known algorithm (classical or quantum) can solve the discrete logarithm problem on properly-sized curves in polynomial time.
  • Statistical resistance: ECC with proper implementation doesn't leak information through patterns (unlike Caesar).
  • This attack exploits implementation weakness, not cryptographic weakness.

Alternative Attacks (if they existed)

  • Side-channel attacks: Timing, power analysis, electromagnetic emanation
  • Implementation flaws: Weak random number generators, nonce reuse
  • Mathematical breakthroughs: New algorithms for ECDLP (none currently known)
  • Quantum computers: Shor's algorithm could break ECC in polynomial time

Conclusion

This homework demonstrates two fundamental cryptanalytic approaches:

  • Exploiting small key spaces: Both schemes fall to brute-force when keys are limited (8 vs 26)
  • Exploiting statistical patterns: Caesar cipher's deterministic nature reveals language structure; ECC's randomization prevents this

The toy ECC scheme fails due to misconfiguration (intentionally small key space), while Caesar cipher fails due to fundamental design flaws (no diffusion, preserves patterns). Properly implemented ECC with full key space remains secure; Caesar cipher does not.
